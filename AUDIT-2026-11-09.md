# SubGate — аудит проекта (2026-11-09)

Аудит только читал код и боевую панель. Изменения в код и панель не вносились.

Проверено:

- Remnawave через MCP, только чтение: `get_metadata`, `get_recap`, `get_users`, `get_node`, `get_hosts`, `get_nodes_metrics`.
- Исходники `remnawave/backend` на коммите `4e98970` (это 3.4.8): список webhook-событий и схема payload.
- Код SubGate: читал сам и с тремя агентами-помощниками. Все ключевые утверждения затем проверены вручную по коду.
- `go test ./core/internal/panel` локально проходит, но только при наличии локального `remnawave-openapi.json`. Последние 4 прогона CI на GitHub упали.

Объём проекта: около 30 тыс. строк в отслеживаемых файлах без `_archive/` и ещё около 9,9 тыс. строк в `_archive/`.

---

## TL;DR

1. **С панелью 3.4.8 проект в целом работает.** Все используемые GET-эндпоинты и поля на месте. Синхронизация users/nodes, node actions и чтение версии совместимы.
2. **Вебхуки фактически не работают.** Код применяет только событие `user.updated`, а в Remnawave такого события нет: есть `user.modified`, `user.created` и т. д. При этом любой вебхук отменяет идущую полную синхронизацию.
3. **Диагностика версии всегда показывает `mismatch`.** Версия сравнивается строго со строкой `3.4.5`.
4. **CI красный последние 4 коммита.** Тест `TestPanelSpecReadContract` и `scripts/generate-panel.py` читают `remnawave-openapi.json`, а этот файл лежит в `.gitignore`.
5. **P0-баг в агенте: через 24 часа аптайма он молча выбрасывает всю телеметрию до перезапуска.**
6. **БД Core растёт без ограничений.** `sg_usage` и `sg_speed_meta` не чистятся, каждая секунда каждого пользователя пишется в 3 таблицы.
7. **Мёртвый код и функции вне задачи — примерно 40–45% кода без учёта `_archive/`.** Это ogen, квоты, block/youtube-проверки, health-кворум и карантин, многопротокольные пробы, nDPI с шейпером, неиспользуемые пакеты и около 30 пустых таблиц схемы.
8. **Панель 3.4.8 сама отдаёт многое из того, что SubGate собирает вручную.** Это скорость интерфейса ноды, нагрузка, `usersOnline`, трафик по inbound/outbound, суточный трафик пользователя по нодам, torrent-blocker и подключения/IP. Уникальная ценность SubGate — **посекундная скорость пользователя, сайты/назначения из access.log, IP/ASN-обогащение и аномалии**. На этом и стоит сосредоточиться.

**Безопасность (хорошо, оставить):** боевой токен возвращает в `rawInbound` приватные ключи REALITY, а в пользователях — `vlessUuid`, `trojanPassword` и `ssPassword`. SubGate их не хранит: `Inbound.UnmarshalJSON` выбрасывает `rawInbound`, `decodeUser` берёт только нужные поля. Для SubGate стоит выпускать **отдельный токен с минимальными scope**: `users:list`, `nodes:list` и чтение recap.

## 5. Что упростить

- **Агент → Core.**
  - Отправлять только пользователей с ненулевой дельтой.
  - Опрашивать StatsService раз в 2–5 с, а не каждую секунду.
  - Агрегировать access.log на агенте: `(user, host, port) → count` за 30–60 с вместо события на каждую строку.
  - Сжимать тело gzip'ом.
  - Объём данных и записи в SQLite должны упасть в десятки раз.
- **Spool агента.** Заменить шифрованный файл с двумя fsync в секунду на ограниченную очередь в памяти, при желании со сбросом на диск при остановке. Секундные скорости переживать сутки простоя не обязаны.
- **`pkg/xray/logs.go`.** Вместо двух регулярок и `time.ParseInLocation` на каждую строку разбирать через `strings.Cut`. Опрашивать раз в 500 мс или через inotify вместо 100 мс. Ограничивать длину строки до чтения, а не после `ReadString`.
- **Хранилище.** Сырые 1-секундные данные хранить несколько часов, рядом держать rollup'ы за 1 минуту и за 1 час (байты up/down по user × node). Retention вынести в отдельный таймер и удалять батчами.
- **SSE.** Один общий broadcast-тикер вместо запроса на каждого клиента. Карты users и nodes держать в памяти и обновлять при синхронизации. Отдельный пул только для чтения в WAL (`MaxOpenConns > 1`) и write deadline для потока.
- **Авторизация.** Убрать `SELECT COUNT(*) FROM admin_users` на каждом запросе (`auth.go:175`) и неиспользуемые колонки TOTP, WebAuthn и ролей.
- **Конфиги.** Сейчас их три варианта: `.env.example`, `core.env.example` и `core.yaml.example`. Оставить один основной, лучше env.
- **`web/app.js`.** 932 строки, но 43 из них длиннее 400 символов, а самая длинная занимает 12 КБ: по сути это код, минифицированный вручную. Отформатировать и разбить по страницам, если консоль будет расти.
- **Документация.** Объединить `PROJECT_PLAN.md` и `DECISIONS.md`. `INDEX.md` дублирует навигацию README.
- **Субмодуль middleware.** Проект независимый, поэтому `git rm --cached remnawave-subscription-middleware` и в README одна строка со ссылкой на upstream. Особые случаи в `.dockerignore` и `check-docs.py` после этого тоже убрать.

## 6. Что не трогать

- `pkg/xray/stats.go`. Это единственный клиент StatsService: дельты, bps, обработка сброса счётчиков, свои дескрипторы без зависимости от xray-core, автопоиск сокета Remnanode.
- `pkg/xray/logs.go` → `Tail` и `ParseLine`: ротация через rename и copytruncate, неполные строки. Упрощать только парсер.
- `agent/internal/{agent,enrollment,preflight}` и `agent/cmd`: цикл сэмплов и heartbeat, проверка, что Core доступен только по HTTPS, enrollment.
- `pkg/wire/wire.go`: компактный формат Sample, Activity, Telemetry и Heartbeat.
- `core/internal/server`:
  - `telemetry.go` (приём данных);
  - `live.go` вместе с `tsdb/live.go` (ограниченный in-memory EMA-store);
  - `analysis.go` и `core/internal/analysis/` (аномалии);
  - `identity.go` (сопоставление email из Xray с пользователем: по id, username, email и shortUuid — устойчиво к любому формату email в Remnawave);
  - `activity_access.go` (rate-limit и аудит чтения журнала).
- `core/internal/panel/client.go` и `inbound.go`: режим только чтения, запрет redirect'ов, лимит ответа 16 МБ, отбрасывание секретов из `rawInbound`.
- `core/internal/{db,config,metrics,ipintel}`, `auth.go`, `clientip.go`.
- `web/`. Все 12 экранов обращаются только к существующим маршрутам, UI подписок не осталось.
- `deploy/`: `install-core.sh`, `install-agent.sh`, `compose*.yaml`, Dockerfile'ы, Caddyfile, `subgate-{core,agent}.service`.
- CI с `-race`, `vet`, проверками установщиков и контейнеров. Нужно только починить C4.
