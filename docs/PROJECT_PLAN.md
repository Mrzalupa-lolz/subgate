# План SubGate: автоматизация мониторинга

Актуально: 2026-11-01. SubGate мониторит Remnawave и внутренний трафик Xray. Подписки и управление подписчиками принадлежат middleware; внешняя DDoS/firewall-защита остаётся отдельным скриптам на нодах.

## Реализовано

- Контур выдачи подписок, request-signals и вкладка пользователей удалены; исходники сохранены в `_archive/monitoring-scope-2026-11-01/`. Снимок аккаунтов Remnawave остаётся для атрибуции.
- Три наблюдения Xray: частота уникальных записей, число IP назначения, число портов одного назначения. Зашифрованные минутные окна, дедупликация, атомарный ingest, очередь разбора, заметки, статусы и аудит.
- Дополнительный Linux worker с отдельным коллектором libnDPI/libpcap: IPv4/IPv6 TCP/UDP, протокол, уверенность, версия, время, счётчики, потери. Payload, адреса и прикладные поля из nDPI в Core не отправляются. Проверены версии 4.14.0 и 4.2.0; последняя даёт недостаточную для автоматики уверенность BitTorrent.
- Длительная перегрузка: ёмкость интерфейса, реальные RX/TX, CPU и потери, последовательные полные минуты, исторический EWMA baseline, hysteresis восстановления. Большой расход сам по себе остаётся наблюдением.
- Атрибуция для конкретной поддерживаемой топологии: выделенные интерфейсы аккаунта, канонический UUID Remnawave, ограниченная по времени эксклюзивная привязка. Общие/NAT/multiplexed сетевые пути без доказанной изоляции работают только как источник наблюдений. Из Xray access.log исходящий сокет автоматически не восстанавливается.
- Автоматическое решение: два разных достоверных nDPI-потока одного выбранного протокола в двух минутах, длительная перегрузка, независимые качественные Xray-счётчики с вкладом аккаунта ≥35%, действующая привязка, исключения и явная политика. Производные одного access.log не считаются независимыми подтверждениями.
- F25 TC/TBF shaper: команды ноды, идемпотентность, fsync-журнал до мутации, абсолютный TTL, локальные исключения, независимый systemd watchdog, rollback, подтверждение применения/снятия и reconciliation. Отмена доступна в UI. Чужой root qdisc не заменяется.
- UI настроек анализа, наблюдений nDPI/перегрузки, состояния коллекторов и команд shaper.

Лимит и срок не назначены автоматически. Автоматика по умолчанию выключена, список ограничиваемых протоколов пуст. Ручной статус «подтверждено» сам по себе не запускает TC.

## Подключение

[NODE_MONITORING.md](NODE_MONITORING.md) описывает сборку nDPI, systemd unit/timer, атрибуцию, пример worker.json, условия решения, TTL и отмену. Worker устанавливается отдельно от непривилегированного основного Agent. Коллектор после открытия capture сбрасывает права; CAP_NET_ADMIN остаётся только исполнителю TC.

Нужны реальные выделенные сетевые пути аккаунтов и их проверенные привязки. Для обычной общей Xray-ноды без таких путей автоматика не включится. Создание маршрутизации/netns/TUN под конкретную инфраструктуру не выполняется этим кодом автоматически.

## Хранение и границы

Xray: UTC-минута, свежесть 2 минуты, максимум 8192 записи на аккаунт/ноду/минуту и 128 назначений для fanout портов. Насыщение видно через `truncated`. Наблюдения — 14 дней, UI 200/API 500. Текущие DPI-метаданные — до 5 минут при ingest, максимум 10000 потоков на ноду; в worker до 64 захватов. Команды и аудит сохраняются для разбора. Неизвестная классификация, потери и неоднозначная привязка не повышают уверенность.

TC не имеет встроенного TTL. Снятие обеспечивают локальный цикл и обязательный независимый systemd timer; ошибки ядра/systemd не скрываются гарантией точного времени. Детали и проверенные ограничения — в [инструкции](NODE_MONITORING.md).

Текущие результаты: [MONITORING_VALIDATION.md](MONITORING_VALIDATION.md). Изменения не публикуются и не развёртываются автоматически.
