# Промпт для Codex: реорганизация документации SubGate

Скопируй всё ниже в Codex (один запуск, не в цикле).

---

Задача: привести документацию репозитория в вид, оптимальный для автономной работы ИИ-агента с минимальным расходом токенов, и составить единый план работ. Работай самостоятельно, не задавай вопросов, в конце дай отчёт.

## Предусловия
1. Создай ветку `docs/reorg` и сделай коммит текущего состояния.
2. Ничего не удаляй безвозвратно: всё, что решишь убрать, переноси в `docs/_archive/` (человек удалит сам после проверки).
3. Ни одно требование, решение или факт не должны пропасть. Если сомневаешься — оставь.

## Источники правды (по приоритету)
1. `subgate-feature-inventory.md` и `subgate-ai-prompt-v4.md` — главные документы, желаемое состояние продукта.
2. Решения пользователя в `docs/DECISIONS.md` и ответы в `docs/registry/QUESTIONS.md`.
3. Остальные docs созданы ИИ и могут быть устаревшими или противоречить п.1–2; при конфликте побеждает п.1–2.
4. Реальный код (`agent/`, `core/`, `pkg/`, `web/`, `deploy/`, `test/`) — истина о том, что реализовано.

## Что сделать

### 1. Аудит
Прочитай все `*.md` в корне и в `docs/` (включая `docs/registry`, `docs/adr`, `docs/runbooks`). Составь таблицу в `docs/REORG_REPORT.md`: файл → размер → суть в одну строку → решение (оставить / влить в X / разбить / архив) → причина.

### 2. Сверка желаемого с реальностью
Для каждой функции из `subgate-feature-inventory.md` проверь по коду и тестам: сделано полностью / частично / не сделано / невозможно. Основывайся на коде, а не на утверждениях в docs. Результат — таблица в `docs/FEATURE_STATUS.md`.

### 3. Слияние `docs/registry/`
- Цель: 10–12 файлов по 3–12 КБ, сгруппированных по доменам (например: panel+ui, nodes+fleet+deployment, security+abuse+anti-scan+geo, telemetry+metrics+health+diagnostics, billing/quotas/subscription, routing+gateway+origins, xray, ops+backups+runbooks).
- Файлы меньше ~1,5 КБ вливай в соседние по теме.
- Файлы больше ~15 КБ (например `health.md`) разбей по смыслу, чтобы агент мог читать только нужную часть.
- Убери дублирование между файлами и между `docs/` и корневыми файлами; оставь одно место для каждого факта.
- В начале каждого файла: 2–3 строки «о чём файл / когда читать».
- `QUESTIONS.md`: оставь только неотвеченные вопросы; ответы перенеси в `DECISIONS.md`.

### 4. `docs/INDEX.md`
По одной строке на каждый документ: `путь — что внутри — когда читать`. Не более 80 строк. Это единственная точка входа в документацию.

### 5. `AGENTS.md` (до 60–80 строк)
Содержит: что за проект (3 строки), команды сборки/тестов/запуска, правила кода и коммитов, правила работы без участия человека (не останавливаться, не спрашивать, блокеры в `docs/BLOCKED.md`, решения в `docs/DECISIONS.md`), таблица «если делаешь X — читай Y», запрет читать целиком `remnawave-openapi.json` и `subgate-ai-prompt-v4.md`. `CLAUDE.md` сделай короткой ссылкой на `AGENTS.md`. `PROMPT.md` — если это дубль, архивируй.

### 6. `docs/remnawave-api-summary.md`
Выжимка из `remnawave-openapi.json`: только эндпоинты, реально нужные SubGate (метод, путь, назначение, ключевые поля). Исходный JSON оставь на месте.

### 7. `docs/PROJECT_PLAN.md` — единый план
Объедини `PROJECT_PLAN.md`, `ROADMAP.md`, `TOKEN_PLAN.md`, `QUESTIONS.md` (открытые) и данные из `FEATURE_STATUS.md`. Формат строго такой:
```
## Этап N — название
- [x] N.1 Короткое имя — что именно сделано (проверено по коду)
- [ ] N.2 Короткое имя — что сделать; критерий готовности: <проверяемое условие, команда или тест>
- [!] N.3 Короткое имя — причина блокера, ссылка на docs/BLOCKED.md
```
Требования: каждый пункт — одна законченная задача на 15–40 минут работы агента с проверяемым критерием готовности; порядок учитывает зависимости; сначала фундамент и то, что блокирует остальное; Xray-редактор в v1 (текстовый), одна учётка без ролей. Пункты, которые уже реализованы, отметь `[x]`.

### 8. Остальное
- `STATUS.md` сократи до короткого журнала (последние ~20 записей).
- `docs/BLOCKED.md`, `docs/DECISIONS.md` — приведи к единому короткому формату, без потери записей.
- Skills: если есть дубли для Codex и Claude, оставь один источник и сделай симлинк для второго (не ломая работу ни одного из инструментов).

## Проверка
- Все внутренние ссылки между md-файлами рабочие (`grep` по ссылкам).
- Общий размер docs (без `_archive`) уменьшился; посчитай до/после в байтах.
- Для 5 произвольных функций из inventory проверь, что агент найдёт нужную документацию через `AGENTS.md → INDEX.md` за не более 2 открытых файлов.

## Отчёт (в `docs/REORG_REPORT.md` и в ответе)
Что слито/разбито/архивировано, размер до/после, честный список: какие функции реально сделаны, какие нет, какие решения ты принял сам, что требует внимания человека. Закоммить всё серией коммитов в ветке `docs/reorg`.
