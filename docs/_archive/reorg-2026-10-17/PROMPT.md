## Источники

## Окружение и безопасность

- Боевая панель: **только GET** (read-only режим по умолчанию, не-GET отклоняется до отправки; покрой тестом).
- Запись в панель: только на тестовой панели.
- Секреты, ключи, UUID пользователей: не печатать, не логировать, не коммитить.
- Решение Q6: одна owner учётка password-only, без TOTP/RBAC.

## Ключевые требования (детали в DECISIONS.md)

- **Квоты:** исчерпанная нода → заглушка «<флаг> У ВАС ЗАКОНЧИЛСЯ ТРАФИК».
- **Детекторы злоупотреблений (F21):** только сигнал, без автодействий.
- **Xray-редактор (F27):** текстовый, подсветка, автодополнение, документация Xray 26.7.28.
- **Журнал активности:** 7 дней hot + 90 дней compressed; бюджет 50% диска, fail-open при превышении.
- **Синхронизация:** вебхуки + опрос 1 мин.
- **Клиенты:** Happ, Incy, mihomo.

## Цикл (для каждого этапа roadmap)

1. **rg** достань строки текущего этапа из PROJECT_PLAN.md roadmap.
2. Если этап зависит от нерешённого вопроса: запиши в BLOCKED, возьми следующий.
3. **TDD:** сначала тесты по критериям готовности, потом код.
4. **make check** (build/vet/test/lint). Для функций с реальной средой: интеграционная проверка на тестовой панели.
5. **После этапов, затрагивающих auth/секреты/API/данные/запись в панель:** запусти security_reviewer **РОВНО ОДИН РАЗ** (не после каждого коммита). Передай ему:
   - список изменённых файлов: `git diff --name-only <начало этапа>..HEAD`
   - инструкцию: «Проверь только эти файлы. НЕ читай docs/, tmp/, remnawave-openapi.json, go.sum, остальной репозиторий.»
6. Только при зелёном: обнови статусы ID в PROJECT_PLAN.md и INDEX.md. Коммит: "<этап>: что сделано".
7. Обнови STATUS.md (3–10 строк: сделано, блокеры, дальше) → следующий этап.

**DONE** только при зелёном тесте или воспроизведённой проверке. «Написано» ≠ «работает».
