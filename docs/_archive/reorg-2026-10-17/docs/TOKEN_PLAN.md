# План сокращения расхода токенов

Дата: 2026-10-14  
Источник: анализ token_report.md, AGENTS.md, PROMPT.md, структуры .agents/ и docs/  
Расход: **96,4 млн токенов** (71,5 млн кэшированных), из них **25 млн (26%)** ушло субагенту security_reviewer  

---

## 1. Топ-5 причин расхода

### 1.1 Избыточная документация (~35–40% общих токенов)
**Оценка:** 30–40 млн токенов на повторные чтения docs/, дублирующих инструкций и больших registry-файлов.

- **PROMPT.md строка 4:** «Прочитай целиком subgate-ai-prompt-v4.md (54 КБ = 13,7k токенов) и subgate-feature-inventory.md (14 КБ = 3,6k токенов)» при каждом старте цикла.
- **docs/registry/:** 47 файлов, 505 КБ (~126k токенов). Самые большие: health.md (45 КБ), activity-journal.md (30 КБ), EVIDENCE.md (30 КБ), activity-storage.md (20 КБ), ROADMAP.md (20 КБ).
- **Перекрытие:** PROMPT.md, README.md, STATUS.md, docs/PROJECT_PLAN.md, docs/registry/OVERVIEW.md — разные версии одного и того же (что делать, какой статус, где что лежит).
- **Устаревшие ИИ-документы:** docs/DECISIONS.md (29 КБ) и docs/registry/EVIDENCE.md (30 КБ) содержат отчёты ИИ, не source of truth.

**Вклад:** ~35% общего input.

### 1.2 security_reviewer без ограничений (~26% общих токенов = 25 млн)
**Оценка:** 25 млн токенов на одного субагента.

- **PROMPT.md строка 39:** «После этапов, затрагивающих auth, секреты, API, данные или запись в панель, запусти read-only security_reviewer и исправь найденное».
- **Проблема:** нет ограничения области проверки — вероятно, субагент читает весь репозиторий (agent/, core/, pkg/, web/, deploy/ + docs/ + remnawave-openapi.json).
- **Skills .agents/skills/security-review/SKILL.md:** 13 КБ общих чек-листов, не специфичных для SubGate.
- **Запуск:** «после этапов» означает множественные вызовы, каждый раз с нуля (субагент не наследует контекст parent-сессии, только инструкции).

**Вклад:** 26% всех токенов.

### 1.3 Мусорные файлы в репозитории (~5–10%)
**Оценка:** 5–10 млн токенов на случайные чтения.

- **remnawave-openapi.json:** 1,6 МБ (~413k токенов) — если Codex читает целиком вместо jq/grep.
- **tmp/:** 37 МБ логов, coverage.out, промежуточных артефактов (хотя в .gitignore).
- **go.sum:** 11 КБ, но бесполезен для ИИ (child-hashes зависимостей).

**Вклад:** 5–10% input.

### 1.4 10 skills, загружаемых на каждом этапе (~5%)
**Оценка:** 3–5 млн токенов на skills.

- **.agents/skills/:** 140 КБ (~35k токенов), 10 файлов по 3–22 КБ.
- **Не все нужны:** tdd-workflow (22 КБ), docker-patterns (17 КБ), golang-testing (17 КБ), deployment-patterns (11 КБ), database-migrations (12 КБ) загружены, но SubGate не использует Docker активно и не требует миграций (SQLite embedded).
- **Перекрытие:** golang-patterns + golang-testing + tdd-workflow дублируют best practices.

**Вклад:** ~5% input.

### 1.5 Инструкции с высоким Input/Output ratio (~204:1 = потеря эффективности)
**Оценка:** косвенный вклад, не отдельная статья расхода, но множитель.

- **token_report.md строка 34:** Input/Output = 204:1, Cached/Output = 158:1.
- **Причина:** Codex читает тонны документации, но генерирует мало кода на выходе.
- **AGENTS.md строка 11:** «DONE только при тесте с нужными assertions и PASS либо ручной behavioral проверке» — каждый этап требует полного цикла read-think-write-test-commit, что накапливает контекст.
- **PROMPT.md строка 4:** «Прочитай... STATUS.md, docs/PROJECT_PLAN.md, docs/registry/INDEX.md, docs/registry/QUESTIONS.md, docs/ENVIRONMENT.md» — 6 файлов при каждом старте.

**Эффект:** множитель 2–3× на все остальные причины.

## 2. Что удалить / вынести / оставить

### Удалить из репозитория
- **remnawave-openapi.json** — вынести в отдельный submodule или docs/external/; читать только через jq/grep. Ссылка в README.
- **tmp/** — уже в .gitignore, но 37 МБ на диске; регулярно чистить (`make clean` target).
- **go.sum** — нельзя удалить (Go требует), но убрать из .claudeignore или эквивалента.
- **docs/DECISIONS.md** (29 КБ) — архивировать вне репозитория, оставить docs/DECISIONS.md с 5–10 строками ключевых решений.
- **docs/registry/EVIDENCE.md** (30 КБ) — архивировать, EVIDENCE не source of truth.
- **docs/registry/activity-journal.md** (30 КБ), **activity-storage.md** (20 КБ) — объединить в один файл docs/registry/activity.md (10 КБ).
- **docs/registry/ROADMAP.md** (20 КБ) — объединить с docs/PROJECT_PLAN.md (18 КБ), единый файл.
- **docs/registry/OVERVIEW.md** (16 КБ) — удалить, это дубликат PROJECT_PLAN.md.

### Оставить (3–4 документа)
1. **AGENTS.md** (сократить до 40 строк, см. раздел 3).
2. **STATUS.md** (1 КБ) — обновляется после каждого этапа, единственный живой статус.
3. **docs/PROJECT_PLAN.md** (объединить с ROADMAP, до 25 КБ) — единый реестр ID, статусы, roadmap.
4. **docs/registry/INDEX.md** (11 КБ) — навигация по областям, оставить как есть.

### Вынести в архив (за пределы репозитория)
- subgate-ai-prompt-v4.md, subgate-feature-inventory.md — прочитать один раз, зафиксировать решения в docs/PROJECT_PLAN.md, оригиналы в архив.
- README.md (9 КБ) — сократить до 2 КБ (ссылки на PROJECT_PLAN, api.md, быстрый старт), убрать дублирование.
- Остальные 40 файлов docs/registry/*.md — по 90% можно удалить или объединить в 5–7 тематических файлов (deployment, health, telemetry, security, panel).

## 3. Короткий AGENTS.md (до 40 строк)

```markdown
# Правила работы с SubGate

## Карта проекта
- Код: agent/, core/, pkg/, web/. НЕ ЧИТАЙ целиком без задачи из roadmap.
- Реестр и roadmap: docs/PROJECT_PLAN.md (единственный source of truth).
- API: docs/api.md, текущий статус: STATUS.md.
- remnawave-openapi.json: НЕ ЧИТАЙ целиком, только jq/grep по ключам.

## Что читать когда
- Старт сессии: STATUS.md (1 стр), PROJECT_PLAN.md (заголовки и текущий этап).
- Задача auth/API: pkg/wire/, core/internal/server/, api.md.
- Задача health/routing: core/internal/server/health*.go, pkg/healthprobe/.
- Задача panel: core/internal/panel/, docs/api.md.
- Задача docs: только файл области из PROJECT_PLAN, не весь registry.

## Ограничения output
- `go test -v`: перенаправь в tmp/test.out, выведи только summary (PASS/FAIL, coverage).
- `make check`: только финальный статус (✓ или ✗), без полного лога.
- Длинные логи > 50 строк: head -20 + tail -10, остальное в tmp/.

## Запреты
- Не читай secrets, .env, keys, существующие DB/backup.
- Не читай весь registry (47 файлов): только PROJECT_PLAN.md и конкретный файл области.
- Не читай remnawave-openapi.json целиком: только `jq '.paths["/api/sub"] | keys'` и т.д.
- Не применяй reset/clean/checkout/restore без поручения.
- Не commit/stage без явного указания.

## Проверка
- `go build ./...`, `go vet ./...`, `go test ./...` — минимум.
- `make check` — полный цикл (race, static, lint), только на Linux с CGO.
- DONE только при зелёном тесте или воспроизведённой проверке.

## Scope
- Цель: самостоятельный продукт владельца, заменяющий remnawave-admin.
- Интеграции: Remnawave (по remnawave-openapi.json) и VPN-ноды.
- Коннектор remnawave-admin НЕ ДОБАВЛЯТЬ.
- Приоритет: Go, скорость, надёжность, минимум слоёв.
```

## 5. Как ограничить security_reviewer

### Текущая проблема
- **PROMPT.md строка 39:** «запусти read-only security_reviewer» без указания области → субагент читает всё.
- **25 млн токенов** на одного субагента = 26% всех расходов.

### Решение: ограничить область
**Изменить PROMPT.md строку 39:**

```markdown
5. После этапов, затрагивающих auth, секреты, API, данные или запись в панель:
   - Запусти security_reviewer только на изменённые файлы: `git diff --name-only HEAD~1 | grep -E '\.(go|js|yaml|env)$'`.
   - Передай субагенту список файлов и строку «проверь только эти файлы, не читай остальной репозиторий».
   - Запускай только в конце этапа (не после каждого коммита внутри этапа).
```

**Добавить в .agents/skills/security-review/SKILL.md:**

```markdown
## Scope для SubGate
- Читать ТОЛЬКО файлы из переданного списка (обычно git diff).
- НЕ читать remnawave-openapi.json, docs/, tmp/, go.sum.
- НЕ читать весь репозиторий без явного списка файлов.
- Фокус: auth (core/internal/server/auth*.go), secrets (.env handling), panel API (core/internal/panel/).
```

### Ожидаемая экономия
- security_reviewer: с 25 млн до ~5 млн токенов (читает только diff, не весь репозиторий).
- **Экономия:** 20 млн токенов = 20% общих расходов.

## 6. Рекомендации по сессиям

### Когда делать /compact
- **Каждые 10–15 этапов roadmap** (сейчас STATUS.md показывает R13–R15, ~3 этапа).
- **При накоплении >500 КБ контекста** (примерно после 30–40 read tool calls на большие файлы).
- **После завершения milestone** (например, «все PARTIAL→DONE для области health»).

### Когда начинать новую сессию
- **После /compact + обновления STATUS.md:** если контекст всё равно раздут (много неудачных попыток, длинные логи в истории).
- **После архивации документов:** когда PROJECT_PLAN.md переписан, старые версии docs/ удалены → начать с чистого контекста.
- **После изменения AGENTS.md/PROMPT.md:** чтобы новые правила применились с начала сессии.

### Где хранить состояние
- **STATUS.md (1 КБ):** текущий этап, сделано, блокеры, дальше (3–10 строк). Обновлять после каждого этапа.
- **docs/PROJECT_PLAN.md:** статусы ID (DONE/PARTIAL/MISSING), roadmap (порядок этапов), единый реестр.
- **НЕ хранить:** промежуточные отчёты ИИ (DECISIONS.md, EVIDENCE.md) — они раздувают контекст.

### Автономность
- **PROMPT.md строка 44:** «При разрастании контекста обнови STATUS.md и продолжай с чистого состояния, перечитав AGENTS.md и STATUS.md».
- **Реализация:** Codex должен сам вызывать /compact, а не ждать команды владельца. Добавить в PROMPT.md:
  ```
  Если контекст >1 млн токенов (cached_input/total >0.5), обнови STATUS.md и вызови /compact.
  ```

## 7. Ожидаемая экономия

### Базовые оценки (от 96,4 млн токенов)

| Мера | Экономия токенов | Экономия % | Обоснование |
|------|------------------|-----------|-------------|
| Удаление дублирующих docs (400 КБ → 100 КБ) | 20–30 млн | 20–30% | Меньше reads на каждом этапе; docs/ сейчас ~505 КБ, после чистки ~100 КБ. |
| Ограничение security_reviewer на git diff | 20 млн | 20% | С 25 млн до ~5 млн (читает только изменённые файлы). |
| Отключение 5 ненужных skills (100 КБ) | 5–10 млн | 5–10% | Skills загружаются на каждом этапе; 100 КБ × 50 этапов = 5 МБ. |
| Вынос remnawave-openapi.json (1,6 МБ) | 5–10 млн | 5–10% | Если Codex читал целиком хотя бы 5–10 раз. |
| Короткий AGENTS.md (3,5 КБ → 2 КБ) и PROMPT.md (10 КБ → 5 КБ) | 2–5 млн | 2–5% | Загружаются при каждом старте; экономия на cache misses. |
| Ограничение output (`go test -v` → summary) | 5–10 млн | 5–10% | Длинные логи сейчас попадают в контекст; после — только summary. |
| **ИТОГО** | **57–85 млн** | **60–88%** | Суммарная экономия от всех мер. |

### Итоговый расход после применения мер
- **Было:** 96,4 млн токенов.
- **Станет:** 11–39 млн токенов (медиана ~20–25 млн).
- **Цель:** сократить в **4–5 раз** (до 20 млн токенов на проект).

### Условия достижимости
- **Обязательно:** удаление дублирующих docs, ограничение security_reviewer, вынос remnawave-openapi.json.
- **Желательно:** отключение лишних skills, короткие AGENTS.md/PROMPT.md, ограничение output.
- **Риск:** если Codex продолжит читать весь registry целиком (не смотря на правила) — экономия будет ниже (~40–50% вместо 60–88%).

## 8. Контрольные метрики (как измерить успех)

После применения мер проверить в следующем token_report:

1. **Total tokens на проект < 25 млн** (было 96,4 млн).
2. **Subagent tokens < 10% общих** (было 26%, станет ~5–10%).
3. **Input/Output ratio < 100:1** (было 204:1, станет ~80–100:1).
4. **Cached input / Total input < 0.6** (было 0.74, станет ~0.5–0.6 из-за меньшего контекста).
5. **Число sessions с >10 млн токенов = 0** (было 1 сессия с 71 млн).
