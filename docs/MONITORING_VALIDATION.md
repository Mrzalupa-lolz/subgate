# Проверки мониторинга — 2026-11-01

Проверена локальная правка на синтетических данных. Рабочая панель и реальные ноды не использовались; публикация и развёртывание не выполнялись. Ниже отдельно описаны первоначальная проверка мониторинга и последующая реализация nDPI/перегрузки/shaper.

## Код

В Ubuntu/WSL успешно выполнены:

```sh
go test ./... -count=1
go vet ./...
go test -race ./core/internal/server -run TestAnalysis -count=1
go test -race ./core/internal/analysis -count=1
```

Полный `go test` прошёл после исправления health/maintenance fixtures: ноды тестов добавлены в синхронизированный реестр. Проверки production-кода и проверяемые условия не ослаблены. Опциональные live-тесты не означают проверку реальной инфраструктуры. Полный race-прогон всего проекта и coverage gate не заявляются.

Для новой аналитики проверены повторная доставка, дедупликация, сохранение после перезапуска, откат общей транзакции, границы окон и памяти, нормализация fingerprint, права API, политика, статусы разбора и аудит.

`node --check web/app.js` и `git diff --check` прошли.

## Синтетический замер ingest

Целевой масштаб по ответу владельца: до 20 нод и 1000 активных аккаунтов. Пиковое число событий в секунду пока неизвестно.

```sh
go test ./core/internal/server -run NoTests -bench BenchmarkTelemetry20Nodes1000Accounts -benchtime=3s -benchmem -count=1
```

Ryzen 5 3500, Linux/WSL, 6 procs. В тесте 20 зарегистрированных нод, по 50 аккаунтов на ноду, начальные окна заполнены 300 записями на аккаунт. Измеряемый путь включает HTTP handler, авторизацию, JSON, шифрование журнала, агрегацию и SQLite commit.

| Пакет | Время на пакет | Событий/с | B/op | allocs/op |
| --- | ---: | ---: | ---: | ---: |
| 50 событий | 6,382 мс | 7835 | 404442 | 6562 |
| 1000 событий | 68,055 мс | 14694 | 4563578 | 50327 |

Дедупликация вынесена из перезаписываемого JSON окна в индексированный SQLite ledger с непрозрачными хешами и коротким retention. В сравнительном запуске пакет из 50 событий ускорился примерно в 5,7 раза относительно 36,49 мс.

**Это SQLite в памяти и httptest внутри процесса.** Замер не включает реальный диск, сеть, параллельный fleet ingest, длительную работу, SSE и UI-нагрузку. Он не доказывает производственную ёмкость, задержку p95 или отсутствие потерь при пиковом потоке. Следующий нагрузочный этап должен измерить эти величины на дисковой базе и реальном профиле событий.

## Первоначальный результат до реализации worker

Работают три объяснимых наблюдения по Xray: частота записей, широта IP назначения и портов одного назначения. Они сами по себе не устанавливают нарушение. Ограничения агрегации и неполнота данных видимы в наблюдении.

На этом этапе nDPI, корреляция независимых источников, анализ длительной перегрузки и исполнитель shaper ещё отсутствовали. Этот статус заменён реализацией ниже.

## Дополнение: nDPI, перегрузка и TC/TBF

Реализованы дополнительный Linux worker, отдельный native-коллектор, независимые источники подтверждения, leased bindings выделенных интерфейсов аккаунта, TC/TBF, журнал намерений, отмена/allowlist/rollback, TTL watchdog и UI. Условия подключения и точные ограничения: [NODE_MONITORING.md](NODE_MONITORING.md).

Проверки выполняются в Ubuntu/WSL, Go 1.26.0. Без production-запросов, изменения конфигурации Remnawave или воздействия на реальные сетевые интерфейсы.

```sh
go test ./... -count=1
go vet ./...
go test -race ./core/internal/analysis ./agent/internal/worker ./core/internal/server -count=1
go test -race ./... -count=1
make build build-worker
make lint
SUBGATE_TEST_TC_NETNS=1 go test ./agent/internal/worker -run TestShaperTCNamespace -count=1 -v
```

Эти проверки прошли. `make lint` включает gofmt, JavaScript syntax, Bash syntax и installer lifecycle. Убраны CRLF из проверяемых shell-файлов, для Linux scripts/units добавлены правила `.gitattributes`.

В тестах проверены: несколько полных минут перегрузки, baseline и восстановление, пропуски/потери/смена ёмкости, restart через persisted state; запрет санкции для guesses, единственного потока, разных протоколов, общего пути, неизвестного аккаунта, просроченной привязки, устаревших ресурсов, выключенной политики и исключений. Happy path проходит через HTTP ingest независимых Xray-счётчиков → monitor/DPI → атомарную команду с аудитом → отчёт применения → отмену → подтверждение удаления. Инъекция ошибки аудита откатывает команду. Повторный batch/flow не создаёт вторую санкцию.

TC дополнительно проверен на настоящем ядре Linux: тест создаёт отдельный network namespace и пару veth, устанавливает TBF в обоих направлениях, проверяет qdisc через JSON netlink/TC и снимает их после истечения срока. Namespace удаляется в cleanup. Это проверка исполнения и TTL, не замер качества/throughput реальной ноды. Отдельные unit-тесты проверяют повторные команды без продления TTL, недоступный Core, частичную установку с rollback, чужой qdisc и повтор очистки после ошибки.

Native-коллектор собран с `-Wall -Wextra -Werror` против libnDPI 4.2.0 из Ubuntu и против nDPI 4.14.0 (tag 4.14, commit `90090b9ae841fce67d00c52ac87e755dcea7c95f`). `python3 test/ndpi_smoke.py` прошёл на обеих версиях. Корпус синтетический, PCAP создаются во временном каталоге:

| Сценарий | nDPI 4.14 | nDPI 4.2 |
| --- | --- | --- |
| BitTorrent handshake, IPv4 и IPv6 | BitTorrent / dpi | BitTorrent / guessed (недопустим для автоматики) |
| HTTP браузера | HTTP / dpi | HTTP / dpi |
| STUN/WebRTC | STUN / dpi | Unknown |
| Игровой Source Engine UDP | Source_Engine / dpi | Unknown |
| Синтетический WireGuard/неизвестный шифротекст | Unknown | Unknown |
| Обрезанный пакет | Потери видны, nonzero exit | Потери видны, nonzero exit |

Проверяется точный allowlist полей stdout: ID, protocol, confidence, version, timestamp, bytes, packets, dropped, truncated. Payload/IP/SNI/infohash/URL не выдаются. Слабая уверенность старой библиотеки сохраняется, а не повышается вручную. Дополнительный PCAP проверяет повторное использование TCP tuple: новый SYN сбрасывает классификатор и ID, последующий HTTP не наследует прежнюю метку BitTorrent. Core исключает из Xray-атрибуции даже канонический ID, если тот одновременно является алиасом другого аккаунта.

Браузерная проверка `python test/monitoring_ui.py DEMO_URL` прошла в Chromium/Playwright против временного Core `-demo -database :memory:`. Проверены вход, сохранение/повторное открытие лимита, срока, списка протоколов и исключений, явное включение/выключение автоматики, пустые состояния подключений/команд, отсутствие JavaScript exceptions и горизонтального переполнения при 390×844. Это синтетическая demo-среда; скрипт отказывается запускаться против обычного Core. [Desktop](screenshots/monitoring-analysis.png), [mobile](screenshots/monitoring-analysis-mobile.png).

Производственная ёмкость 20 нод / 1000 аккаунтов, полнота классификации реального VPN-трафика, созданные оператором выделенные сетевые пути и точность атрибуции в конкретной инфраструктуре пока не подтверждены. Автоматика по умолчанию выключена; лимит/TTL/протоколы не выбраны. Сам по себе ручной статус confirmed сетевую команду не создаёт.
